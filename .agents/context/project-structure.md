# Project Structure

Where things go. `ls` shows what is there; this file says where a new thing belongs.

```
bifrost/
├── CLAUDE.md · AGENTS.md      # agent entry points → .agents/
├── bifrost                    # `./bifrost`: the repo task runner (scripts/bifrost/); NOT the LAN client (cli/)
├── .agents/                   # context/, rules/, memory/, plans/; skills → .claude/skills/
├── .github/workflows/         # ci.yml, release.yml, audit.yml, sync-develop.yml
├── package.json               # npm workspaces: server, client, web, cli, e2e; root `overrides`
├── ecosystem.config.cjs       # PM2 apps (API, web host, mDNS), chosen by the launcher's flags
├── docker/ · compose/         # one Dockerfile per image; one compose file per piece
├── docker-compose.yml         # includes api + web + observability: `docker compose up` is the hub
├── observability/             # Loki, Alloy, Prometheus, Tempo, Grafana configs and dashboards
├── docs/                      # human docs: DESIGN, THEME-SPEC, testing, standalone, pm2/launchd, docker, releasing…
├── server/
│   ├── drizzle/               # generated migrations (never hand-edited; see the db-migration skill)
│   ├── openapi.json           # generated by `./bifrost spec`; committed; a test fails while stale
│   └── src/
│       ├── app.ts             # composition root: DEPLOY_PROFILE manifest → modules
│       ├── bootstrap.ts       # production entry
│       ├── otel.ts            # tracing, loaded with `node --import` before the app
│       ├── testing/app.ts     # createTestApp: the one way a server test builds an app
│       ├── core/              # shared kernel; never imports modules/
│       └── modules/<feature>/ # module.ts, ports.ts, routes/, usecases/, services/
├── web/src/                   # the web host: host.ts (static + proxy), mdns, run modes, standalone rules
├── client/
│   ├── *.ts                   # Vite plugins: seoBuild, precompress, bundleBudget, fontPreload, inlineCss
│   └── src/
│       ├── main.tsx           # entry (starts the drafts tab session)
│       ├── app/               # shell, router, nav, season.ts, cross-feature pages (Midgard, hubs, Pensieve)
│       ├── core/              # shared client kernel: api/sse, ui/, theme/, json/ yaml/ xml/ markdown/,
│       │                      #   library/, drafts/, settings/, notify/, decor/, guide/, *Seed.ts hand-offs
│       ├── features/<feature>/ # one folder per page or tool; never imports another feature
│       ├── seasons/<name>/    # plug-in seasonal decorations; only app/season.ts imports one
│       └── assets/            # fonts, relic drawings, themes/*.json
├── cli/src/                   # the `bifrost` LAN client: commands/ over core/; output.ts owns the terminal
├── e2e/                       # browser/ (Playwright), api/, cli/, standalone/, perf/, support/; imports no product source
├── scripts/                   # task-runner commands, launchers, backup, resilience, generators
├── tools/micromatch-shim/     # in-repo replacement for micromatch (see decisions, dependency overrides)
└── storage/                   # gitignored: uploads/ downloads/ tmp/ data/(app.db) logs/
```

## Placement rules

- **Code shared by two features** moves to `core/` at its second consumer, not before.
- **A page across features** (the Pensieve, the category hubs) lives in `client/src/app/pages/`; its logic in `core/`.
- **Only the composition roots reach across features:** `server/src/app.ts` and `client/src/app/`.
- **A Drizzle table** goes in `server/src/core/db/schema.ts` (drizzle-kit reads only that file), with a comment naming the module that owns it; see the `db-migration` skill.
- **Tests sit beside the code** (`*.test.ts`, `*.int.test.ts`); end-to-end tests go in `e2e/`.

## Naming

Modules and server files kebab-case; client files camelCase, components PascalCase; classes PascalCase with a role suffix (`UploadFilesUseCase`, `FileStorageRepository`); events `<module>.<event>` (`file.uploaded`, `download.added`).
