# Tech Stack (decided — do not swap without a logged decision)

| Concern | Choice | Why |
|---|---|---|
| Runtime | Node.js ≥ 20, TypeScript strict | Owner's existing Node/mDNS/WebSocket experience; typed contracts for themes/config/API |
| HTTP server | Fastify 5 | Plugin encapsulation maps to feature modules; built-in schema validation; first-class streaming; pino-native |
| Frontend | React 19 + Vite, vertical-slice `features/` folders, route-level code splitting | Dynamic theming, admin forms, live lists need components; splitting keeps cloud builds free of local-only UI (was React 18 at planning time — see decision log 2026-07-12) |
| Styling | Plain CSS + CSS custom properties (no Tailwind) | Themes are JSON → CSS variables on `:root`; hot-swappable, framework-agnostic |
| DB | better-sqlite3 + Drizzle ORM, WAL mode | Embedded single file, zero babysitting, restart-tolerant; Drizzle gives typed schema + migrations; repository interfaces keep Postgres swap mechanical for cloud profile |
| Uploads | @fastify/multipart (busboy) | Streams to disk, flat memory at 2 GB; temp-file + atomic rename |
| File watching | chokidar (`awaitWriteFinish` on, `depth: 1` since PLAN-24) | FSEvents-native on macOS; debounces half-copied files; used by VS Code/webpack. The depth is the **structural** enforcement of "downloads/ is one level deep" — application code never counts path segments, so a file two levels down is simply never seen |
| Live updates | Server-Sent Events (one hub) | One-directional notifications; browser auto-reconnect; ~20 lines vs WS lifecycle management |
| mDNS | bonjour-service | Advertise `bifrost.local`; Android fallback = LAN-IP QR code printed at boot + shown in Heimdall |
| Config | dotenv + zod validation at boot | Fail fast on bad env; `.env` = defaults + secrets, DB `settings` table = runtime-mutable values (admin shortcut, etc.) |
| Logging | pino → JSON file (`storage/logs/`) + pino-roll rotation; pino-pretty in dev | Structured lines per module/request; the optional observability stack tails these files |
| Admin sessions | @fastify/secure-session (stateless secretbox cookie) + revocable session epoch in DB settings | No server-side session store to babysit; epoch bump = revoke-all that survives restart (see decisions 2026-07-15) |
| Device labels | ua-parser-js (server-side) | Presence turns UAs into "iPhone · Safari" labels; character aliases layered on top (PLAN-06) |
| Theme validation | ajv against a published JSON Schema | Users add themes as JSON; schema is the contract (THEME-SPEC.md) |
| JSON editor & tooling (client) | CodeMirror 6 (`@codemirror/*`, incl. `merge` for diff chunking and `search` for in-editor find) + jsonc-parser | Runestone/Variant need a real code editor (lint, fold, highlight, auto-close, find); jsonc-parser gives token-preserving format/minify that keeps > 2^53 precision. Shared `core/ui/JsonEditor` mounts in both features (PLAN-07/08); its find + Variant cross-pane reveal is shared so Edda (PLAN-11) inherits it |
| YAML (client only) | `yaml` (eemeli) v2 + `@codemirror/lang-yaml` | Groot (PLAN-19) needs a **comment-preserving document model** — `js-yaml`'s parse+stringify deletes every comment, which for a config file is silent data loss — plus multi-document support, errors with source offsets for the lint gutter, and YAML 1.2 by default. `lang-yaml` already folds `Pair`/`Item`/`BlockLiteral` and both flow collections, so no custom `foldService` (unlike Loki's). **The server never parses YAML**: alias expansion is a billion-laughs amplifier, so the byte cap does not bound a parse — the browser parses under `maxAliasCount` |
| Zip streaming (server) | `archiver` | PLAN-24's folder → .zip download streams incrementally into the HTTP response — no full-archive buffer, no blocking `spawnSync` in the request path, which is what several devices asking for a folder of large media at once needs. `core/backup` keeps shelling out to the `zip` CLI: that one is a rare, synchronous, whole-process snapshot, not a per-request stream. Confined to `services/fs-folder-archiver.ts` — no usecase or route imports it |
| Unified diff formatting (client) | `diff` (jsdiff) | PLAN-26's text-mode export needs a real unified-diff **file** — context lines, hunk merging when two changes sit close together, `@@ -l,s +l,s @@` headers, the `\ No newline at end of file` marker. `@codemirror/merge`, already here for the on-screen diff, gives changed-line ranges and none of that formatting. Small, dependency-free, and the package most JS tooling already builds on, which is the point: the owner's ask was that the output look the same as other tools, not merely be correct. The RFC 6902 side needed no dependency at all — `core/json/jsonPatch.ts` maps PLAN-08's own diff records and is small enough to property-test directly |
| Brotli codec (server) | Node's built-in `zlib` — **no new dependency** | Worth stating explicitly, since every other recent addition to this table *was* a package: PLAN-25 adds none. `zlib` has carried Brotli since Node 11.7, backed by Google's own `libbrotli` — the same reference implementation every browser decoder and the standalone `brotli` CLI use, so what Bifrost produces is byte-format standard. The alternative was a bundled WASM codec in the client, because browsers' `CompressionStream` supports gzip/deflate only and has no Brotli format at all; that would have cost every other tool bundle size for one page's benefit. Confined to `services/node-brotli-codec.ts` — no usecase or route imports it |
| CLI argument parsing | `commander` | PLAN-27's `bifrost` binary. The same reasoning `archiver`/`diff`/`open` got: a small, single-purpose, de-facto-standard library doing something genuinely fiddly by hand — subcommands, `--flag=value` vs `--flag value`, short-flag bundling, `--help` generation, exit codes. The config-file path and the GitHub version check are hand-rolled instead, because neither is fiddly enough to earn a dependency |
| Browser launching (CLI) | `open` | `preview` (default-on) and `portkey go --open` share one launcher. `start` / `xdg-open` / `open` differ per platform and carry real shell-quoting hazards. Name coincidence only: the `open` **package** and the `bifrost open` **command** are unrelated, and no user ever sees the dependency's name |
| Man page (CLI) | `marked-man` (devDependency) | `cli/man/bifrost.1.md` is hand-written and compiled to real roff at build time by `scripts/gen-man.ts` — `gen-build-info.ts`'s pattern, a generated file nobody hand-writes, gitignored. roff/troff macro syntax is exactly the "fiddly by hand" bar; and it is the same author family as the `marked` the client already carries for Edda. Stated honestly: the man page and `--help` are kept in sync **by hand**, since build-time introspection of commander is more machinery than a CLI this size warrants |
| CLI file upload | Node's built-in `node:http` — **no dependency, and not `fetch`** | PLAN-27's mandated spike measured this rather than assuming it, and it came back the **opposite** way to the plan's premise: `fetch` + `FormData` (even with `fs.openAsBlob`) buffers the whole file — ~412 MB of live set for a 400 MB upload — and a `duplex: 'half'` stream body does too. `node:http` with the multipart envelope piped in holds ~23 MB for the same file. So `client.ts` keeps `fetch` for every other call and pipes uploads through `node:http`. The plan's own fallback, `undici`'s low-level API, was not needed and would have been a real dependency on an installed CLI (Node bundles undici internally; the package is not there unless declared) |
| PDF rendering (client) | `pdfjs-dist`, its **`legacy/` build**, lazy-loaded in its own chunk | PLAN-29's second Saga slide source. Rendering a PDF page to pixels is a parser, a font engine and a rasterizer — the exact opposite of the "small, single-purpose" bar the other additions cleared, and correspondingly the one place where writing it is not on the table; pdf.js is also what every browser's own viewer descends from. **`legacy/` is not a preference**: 6.x calls `Promise.try`, so the default build throws on Node 22 (the unit tests could not run against it) and on any iPad or iPhone more than a release or two old — which is who presents from a LAN. The worker is a plain Vite `?url` import, proven against the built bundle, so the plan's `disableWorker` fallback went unused. `wasmUrl` **is** set, from `scripts/copy-pdf-wasm.ts` — 6.x moved JBIG2/CCITTFax, JPEG 2000 and colour management into wasm, and without it a scanned PDF renders as blank white pages with no error at all. `standardFontDataUrl` and `cMapUrl` are deliberately unset: `useSystemFonts` defaults to `!isNodeJS`, so a browser resolves the standard 14 fonts against its own, and 2.5 MB of font and cmap data is not shipped to serve CJK-encoded decks — the stated limitation |
| Lint/format | ESLint + eslint-plugin-boundaries + Prettier | Boundaries plugin mechanically enforces module isolation |
| Commits | commitlint + husky, Conventional Commits | Owner's established discipline; scopes = module names |
| Tests | Vitest (+ supertest via fastify.inject) | Fast, TS-native, same tool front+back |
| Process manager (macOS run mode) | PM2 or launchd | Native run keeps mDNS/FSEvents working. Both crash-restart + start-on-boot; PM2 adds live monitoring, launchd needs no install. `ecosystem.config.cjs` + one-command `scripts/start-pm2.sh` / `start-launchd.sh`; runs `server/dist/bootstrap.js` (app.ts's direct-run guard doesn't fire under PM2's fork wrapper) — see docs/pm2.md, docs/launchd.md |
| Docker (Linux target) | Multi-stage Dockerfile + compose | NOT the macOS run mode (mDNS/FSEvents/Finder break in the Docker VM). Ships for a future Linux host (`--network host`); CI builds it every PR to keep it honest — docs/docker-linux.md |
| Observability (optional) | Grafana + Loki + Alloy + **Prometheus + Tempo** (`docker-compose.observability.yml`) | Alloy tails `storage/logs/*.log` → Loki → Grafana; files-first so it's fully detachable and backfills. Prometheus scrapes `/metrics` (`prom-client`) and Tempo receives traces — both are **accelerators**, never the durable record, because a scrape gap can't be backfilled and a push can be dropped. Alert rules query Loki, not Prometheus. `node_exporter` deliberately excluded — docs/observability.md |
| Tracing (off by default) | OpenTelemetry SDK (`@opentelemetry/sdk-node` + auto-instrumentations) → OTLP/HTTP | `OTEL_ENABLED=false` ships as the default; loaded with `node --import ./server/dist/otel.js` because ESM hoisting means an SDK started from app code instruments nothing, silently (see decisions 2026-07-29) |
| Backup/restore | better-sqlite3 `VACUUM INTO` + `zip`/`unzip` | Online-safe DB snapshot (consistent under WAL) + archive of `storage/` + `themes/`; `core/backup` reused in-process by PLAN-10's button — docs/releasing.md for state boundaries |
| Release automation | GitHub Actions (`release.yml`) + changelogen | On push to `main`: semver from conventional commits → bump + CHANGELOG → tag → GitHub Release + tarball → `main`→`develop` back-merge; needs a `RELEASE_TOKEN` PAT — docs/releasing.md |

PWA: static `web app manifest` + icons in `client/public/` (favicon SVG + PNG fallbacks, `apple-touch-icon`, 192/512 "any" + maskable icons) — no service worker (LAN app, no offline story needed). Vite copies `public/` to the dist root; `@fastify/static` serves it (manifest as `application/manifest+json`). Brand mark = the Bifrost rainbow bridge — a glowing teal→(deep purple)→green arch between two lit "realm" nodes over a near-black starfield with a corner vignette (owner-chosen "Pure Arch", iterated for a dark, no-white-strip look). Raster icons render from a one-off Node generator; `favicon.svg` mirrors the same geometry.

Deferred/optional: Postgres (cloud profile), PWA service worker / offline caching.
